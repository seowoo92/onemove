# 개발일지 2026-07-26 (일) — 기획안·안내서·웹 푸시 완성 + 카카오 카드 실험

## 1. 제출 문서 초안 작성 (저장소 외부 관리)
- 상세 내용·소스는 저장소 미포함 경로에서 관리

## 2. 사용자 안내서 (설정 탭)
- 진입: 설정 헤더 우측 "사용법 안내 ›" 칩(**B안** — 설정 한 화면 원칙 유지). GuideScreen 신설
- 레이아웃 3안 비교 → **그룹 카드 확정**: 섹션(흰 카드+연녹 헤더 띠) 안에 아코디언 행, 섹션·항목 14px 통일
- 항목 9개 문구 사용자 확정. 모바일에서 고정 탭바가 마지막 카드 37px 가리는 버그 발견 → 하단 패딩 96px(수치 검증)

## 3. 시스템 alert → 인앱 토스트
- 홈 2곳(카톡 재발송 결과·★ 3개 제한) 교체 — 화면 정중앙, 딥그린 0.86+블러, 3.2초 자동 소멸, 문장 단위 줄바꿈(pre-line+keep-all)

## 4. 카카오 루틴 카드 — 피드 실험 끝에 텍스트 확정 (중요 교훈)
- 피드(카드) 템플릿 실기기 검증 결과: **이미지 2:1 강제 크롭, 아이템 행 이름 6자 말줄임 + 위치 제목 위 고정, 본문 2줄 잘림** → 루틴 목록 수용 불가
- 날씨 배너 3종(800×400) 제작·카드+목록 2연발까지 시도 → "목록이 핵심"이라 **텍스트 한 통으로 회귀**(사용자 확정). 버튼은 스펙상 제거 불가(기본 '자세히 보기') → '오늘만큼 열기' 지정
- 결정 근거를 send-kakao 코드 주석에 기록. 잔재: public/images/kakao-banner-*.png (리포 정리 때 제거 가능)

## 5. 웹 푸시 알림 완성 (실기기 검증까지)
- 구성: 푸시 전용 SW(public/push-sw.js, 캐싱 없음) · src/lib/push.js(VAPID 공개키 내장) · 설정 알림 카드 2행째 "앱 알림" 토글+[테스트] 칩 · push_subscriptions 테이블(RLS) · send-push 함수(jsr:@negrel/webpush) · remind-incomplete 2채널화(카카오·푸시 독립)
- **VAPID 키**: Secret `VAPID_KEYS`(JWK 쌍) — 로컬 백업 vapid-keys.local(리포 루트, gitignore). 분실 시 재생성하면 기존 구독 전부 무효
- 실기기: 토글→권한→테스트 알림 수신, **알림 탭 → 설치된 PWA 직행** 확인 (카카오 버튼이 인앱 브라우저로만 열리는 iOS 한계의 해법)
- 문구 확정: 리마인더 제목 "{닉네임}님, 오늘 하루 어땠나요" / 본문 "남은 루틴은 가볍게 하나만 정리해봐요." — 제목이 앱 이름이면 iOS "from 오늘만큼" 표기와 중복돼 보여서 제목에 실제 메시지. "from" 줄 자체는 iOS 강제 표기라 제거 불가

## 6. 기타
- 설정 세로 압축(베젤이 모바일보다 상하 패딩만큼 좁음 — 라벨·카드 패딩 축소로 한 화면 유지)
- 카카오 콘솔 앱 아이콘 교체(사용자 직접) — 메시지 하단 로고 현행화
- 서버 반영 워크플로우 재확인: **Edge Function은 대시보드 붙여넣기 필수** (커밋만으론 미반영, 코드 전문을 채팅에 제공하는 방식으로 진행)

## 교훈
- 카카오 메시지 템플릿은 칸별 글자수·비율 제약이 강해 "디자인"의 실질 수단은 이미지뿐 — 목록형 콘텐츠는 텍스트 템플릿이 정답
- iOS 웹앱 푸시의 "from {앱명}"은 시스템 표기(제거 불가) — 알림 제목에 앱 이름을 넣지 말 것
